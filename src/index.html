Where risk accumulates in requests

A model trained on ten years of commit history in psf/requests, predicting which files are most likely to need a bug fix next, based on how often a file changes, how much, and by how many people.

Built by Elif Nalan Mutlu · GitHub Repository

01

Mine

PyDriller walks all 6,500 commits, tracking churn, commit count, and unique authors per file: merging history across renames, like the repo's move into src/.

02

Label

Commit messages are matched against fix/bug/error keywords. A file is labeled high-risk if its bug-fix ratio sits above the 75th percentile.

03

Split

Files are ordered by last-modified date and split 80/20. Training only on the past, testing only on commits made after Feb 2025, to avoid leaking the future into training.

04

Train

A logistic regression on standardized churn, commit count, and author count reaches 0.75 AUC on files it has never seen.
